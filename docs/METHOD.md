# The method: carry a concept end to end through a metaphor

Higher-level engineering through AI prompting. You do not have to know how to code to code anymore — you have to carry a concept end to end through a metaphor.

## What changed

The old skill was writing code. The new skill is holding a design clearly enough that a model can build it. The code is no longer the bottleneck. The bottleneck is the concept: knowing what you are building, and holding it steady from the first sentence to the last file.

## The metaphor is the vehicle

A metaphor holds the whole design in one image. It is a compression: everything the system is, in a shape you can keep in your head.

- A door behind a door: an event knocks by writing, an agent knocks by polling. Two rooms, two kinds of knock. That one image produced the whole push/poll design.
- A harness that builds itself: a small file that starts as a chat and ends as a command center. That one image is this product.
- Mold, then cast, then motor, then train, then finish: the locked physics of a machine, in order, no step skipped.

Pick the metaphor first. Then carry it. Every decision gets checked against it: does this fit the image? If it does not fit, either the decision is wrong or the metaphor is. Change one of them deliberately, never both at once, and never silently.

## Hold it steady

The model builds from the metaphor you hold. Hold it steady and the build stays coherent: the same image, the same names, the same order, all the way through. Let it drift — a different image in the second paragraph, a renamed part in the third file — and the build drifts with it. The model cannot tell which version of the metaphor you meant. You have to.

This is the discipline: one image, carried end to end, through every prompt, every file, every decision. The metaphor is the spec. The code is what falls out of it.

## Why this matters for access

This is what makes building accessible. You do not need to know syntax, frameworks, or toolchains. You need to know how to think clearly in metaphors: to see the thing you want, name it in an image, and hold that image steady while the model builds it.

Anyone who can think clearly in metaphors can build. That is how this project was built — a household's whole AI stack, first built by free cloud models, guided by concepts carried through metaphors — and it is how this file teaches others to build.

## The rules

1. **Concept first, code second.** Name the image before you ask for anything.
2. **One metaphor per system.** If you need two, you have two systems. Say so.
3. **Check every decision against the image.** If it does not fit, fix the decision or fix the metaphor, deliberately.
4. **Never let the metaphor drift silently.** A renamed part is a decision. Say it out loud.
5. **The metaphor is the spec.** If the code contradicts the image, the code is wrong.
